WikiJS

Applicazione web client-side per costruire una knowledge base interrogabile dai propri documenti: carichi i file, la KB viene compilata in pagine wiki con citazioni verificate e la conversazione risponde solo con ciò che è presente nella wiki.

Nessuna build e nessun backend applicativo: moduli ES e less.js girano direttamente nel browser; dati e motore vivono in IndexedDB.

Avvio

python3 -m http.server 8123
# aprire http://localhost:8123/static/index.html

Il server va avviato dalla root del repository (in alternativa http://localhost:8123/, che reindirizza all'app). Con file:// i moduli ES e i .less non vengono caricati.

Il vecchio motore (lunr/compromise, Web Worker, prompt dedicati) è stato rimosso: il pacchetto kb/ usa IndexedDB nativo e non conosce provider, chiavi o modelli.

Storage

  • wikijs:<kbId> — un database IndexedDB per knowledge base: meta, sources, pages, catalog, logs, outputs, jobs, staging.
  • wikijs_app_<userId> — Dexie applicativo: kvStore (conversazione, marcatori, archivi rag_kb_*/rag_convo_*) e settings (active_kb, tema, provider, chiavi API).
  • wikijs_llm_<userId> — Dexie dei modelli: discovered-models e selected-models.

I database dell'applicazione precedente non sono migrati: al primo avvio si riparte con storage vuoto (identità ospite wikijs_guest_<timestamp>). Il Reset elimina anche i database wikijs:* e i residui legacy.

Knowledge Base

Compilazione («Crea»)

«Crea» elabora solo i documenti nuovi o modificati (mode:"auto"; su KB vuota equivale a full) e non rielabora mai una sorgente già completata, anche dopo una build interrotta. Ogni sorgente è divisa in chunk deterministici (da 8000 a 40000 caratteri secondo la finestra del modello, coda 1/8), ogni chunk produce una chiamata LLM validata con retry; il merge è per aggiunta e le citazioni sono verificate per sottostringa. I job sono riprendibili: interrompere la compilazione conserva lo staging e non duplica pagine.

Interrogazione

Index-first dal catalogo, con modalità llm (≤ 2 chiamate), llm-min (1) e offline (0). La risposta usa solo le pagine caricate, cita [[slug]] e mostra Fonti verificate e provenienza. La conversazione è stateless: ogni «Avvia/Continua» riesegue la query con l'ultimo messaggio utente; «Visualizza Contesto» mostra l'ultima query. STOP aborta build e query (interruzioni 499 ignorate dalla UI).

Gestione

Archivia salva un bundle JSON nel record rag_kb_<nome> (il dato vero è kbBundle); Carica importa con kbImport(mode:"replace"); Cancella elimina il database della KB attiva e i marcatori; Reset elimina tutti i database wikijs:* e lo stato locale. Gli archivi precedenti (con indice serializzato) non sono convertibili.

API da console

window.kbInit / kbAddSource / kbBuild / kbUpdate
window.kbQuery / kbStatus / kbExport / kbImport / kbLint / kbGetId

L'adapter LLM è iniettabile: activateProviderAdapter() usa window.WikiJsLlm (ospite) o il provider configurato; setAdapter(createMockAdapter()) da js/kb/index.js abilita le prove deterministiche. Gli invarianti I1–I10 si verificano con kbStatus().invariants.

LLM

Provider e modelli si scelgono dal pulsante LLM o dal menu. Le chiamate ritentano 3 volte sui codici transitori; sul 429 applicano backoff e spaziatura adattiva e, se persiste, interrompono il job con stato rate_limited. Onorano signal e propagano l'usage. Senza adapter la query degrada a offline e la build fallisce in modo dichiarato. Gli eventi d'uso sono inviati con nome applicazione wikijs all'endpoint https://wwwanalyzer-backend.workerua.workers.dev (disattivati in locale).
