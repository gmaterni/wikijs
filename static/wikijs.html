wikijs

La wiki che risponde solo con i tuoi documenti. Nient'altro.

Knowledge Base locale. Citazioni verificate. 100% Client-Side. Zero Build.

Cos'è wikijs?

wikijs è un'applicazione web client-side per costruire una knowledge base interrogabile dai propri documenti: carichi file PDF, TXT o DOCX, la KB viene compilata in pagine wiki con citazioni verificate e la conversazione risponde solo con ciò che è presente nella wiki.

"Nessuna allucinazione: se l'informazione non è nella wiki, la risposta lo dichiara — con Fonti verificate e riga di provenienza per ogni affermazione."

I Caratteri Originali del Progetto

Frontend 100% Client-Side

JavaScript vanilla con ES Modules caricati nativamente dal browser. Nessun framework, nessun bundler, nessun transpiler: il codice che leggi è quello che il browser esegue. Stili LESS compilati a runtime da copia locale, senza CDN, e layout a due pannelli invariato (barra fissa, drawer laterale, output/input, overlay STOP, finestre fluttuanti, tooltip).

Vanilla JS ES Modules LESS Zero Build

Wiki Verificata, Non Chat Libera

Ogni risposta cita pagine con [[slug]] e mostra Fonti verificate: solo citazioni verbatim verificate per sottostringa — una parafrasi corretta ma non letterale viene scartata. Slug deterministici mai generati dall'LLM, contraddizioni in append (mai cancellazioni), pagine in quarantena escluse dalle query.

[[slug]] Verbatim No Allucinazioni

Compilazione Incrementale e Riprendibile

Il comando Crea elabora solo sorgenti nuove o modificate (mode:"auto", su KB vuota equivale a full) e non rielabora mai una sorgente completata, anche dopo una build interrotta. Chunk deterministici da 8000 a 40000 caratteri secondo la finestra del modello (overlap 1/8), una chiamata LLM validata con retry per chunk, merge per aggiunta. I job sono riprendibili: STOP conserva lo staging senza duplicare pagine.

Incrementale Riprendibile Retry + Backoff

Libertà LLM, Chiavi al Sicuro

Stessi 5 provider di sempre — Gemini, Mistral, Groq, OpenRouter, HuggingFace — con catalogo locale (static/data/models/*.txt) e scoperta remota con probe e voto. Chiavi di prova già pronte, chiavi personali solo sul dispositivo (mascherate, attivabili/eliminabili). Query index-first con modalità llm (≤2 chiamate), llm-min (1) e offline (0 chiamate, selezione locale).

5 Provider Solo sul Dispositivo Offline

Avvio in Locale

Nessuna build, ma serve un server statico: con file:// i moduli ES e i .less non vengono caricati. Dalla root del repository:

python3 -m http.server 8123
# aprire http://localhost:8123/static/index.html

In ambiente locale il login Google è bypassato (user_local) e la telemetria è disattivata.

Cosa Trovi nell'App

  • Knowledge Base: Crea (solo new/changed), Cancella, Archivia (bundle JSON in rag_kb_<nome>), Gestisci, Ripristina da file, Documenti Processati (ingested vs new/changed/error), Gestione Documenti, Riepilogo Dati.
  • Query indipendenti: pulsante Invia (o Enter) riesegue sempre kbQuery({ kbId, question, mode: "llm" }) — ogni domanda è indipendente, senza riuso di stato. STOP aborta build e query (interruzioni 499 ignorate dalla UI).
  • Conversazione: visualizza storico, cancella vista, archivia/gestisci/ripristina chat — outputs e logs restano append-only (invariante I6).
  • LLM: Test LLM sui modelli selezionati, Reset LLM dai file locali, Aggiorna LLM (scopre, testa e vota), Seleziona LLM (spunta i validati). Retry ×3 su 408/500/502/503/504, backoff su 429 con stato rate_limited, usage reale su Log.
  • API Key: API Keys Default (ricarica offuscate da static/data/api_x.json) e Gestisci API Key (aggiungi/attiva/elimina per provider).
  • API da console: window.kbInit / kbAddSource / kbBuild / kbUpdate / kbQuery / kbStatus / kbExport / kbImport / kbLint / kbGetId — adapter iniettabile (window.WikiJsLlm o setAdapter(createMockAdapter())), invarianti I1–I10 via kbStatus().invariants.
  • Temi dark/light: selezionabili e persistiti, dark di default; risposte in markdown via marked locale.
  • Telemetria minima e trasparente: eventi con nome app wikijs verso il worker WWWANALYZER, disattivati in locale (static/js/services/config.js, sender.js).

Gestione Memoria

Browser Storage

Un database IndexedDB per KB (wikijs:<kbId>: meta, sources, pages, catalog, logs, outputs, jobs, staging), più Dexie applicativo wikijs_app_<userId> (kvStore + settings: active_kb default demo, tema, provider, chiavi) e Dexie modelli wikijs_llm_<userId> (discovered-models, selected-models). Riapri il browser e ritrovi tutto. Reset elimina anche i wikijs:* e i residui legacy.

Login Solo in Produzione

Accesso con Google (login.html, identità in localStorage.user_web_id con isolamento DB per utente). In locale il login è bypassato (DISABLE_LOGIN_ON_LOCAL → user_local): apri e lavori subito, i dati non lasciano mai il dispositivo.
