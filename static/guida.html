wikijs - Guida Utente

Introduzione

wikijs costruisce una knowledge base interrogabile dai tuoi documenti: carichi i file, la KB viene compilata in pagine wiki e ogni domanda riceve una risposta basata solo su ciò che è nella wiki, con citazioni [[slug]] e Fonti verificate. Tutto è 100% client-side: nessun server, nessun account, nessun build.

"Nessuna allucinazione: se l'informazione non è nella wiki, la risposta lo dichiara — con la riga di provenienza per ogni affermazione."

Primi Passi — in 3 step

Dal caricamento alla prima risposta verificata. Bastano pochi minuti (+ il tempo di compilazione).

1. LLMProvider + chiave + modello
→
2. CompilaUpload + Crea KB
→
3. DomandaInvia e leggi le fonti
→
4. IteraNuovi doc → Crea
→
5. ArchiviaKB e chat salvate
1 Configura l'LLM

Premi il pulsante LLM nella barra superiore e scegli un provider (Gemini, Mistral, Groq, OpenRouter, HuggingFace), poi un modello. Al primo avvio trovi chiavi di prova già pronte: puoi partire subito, per l'uso quotidiano aggiungi la tua chiave in Menu → API Key → Gestisci API Key (resta solo sul tuo dispositivo).

2 Carica i documenti e crea la KB

Premi Upload e seleziona file .txt, .pdf, .docx o .odt. Poi vai su ☰ Menu → Knowledge Base → Crea: elabora solo le sorgenti nuove o modificate, mostra l'avanzamento nel Log e puoi interrompere con STOP (il lavoro fatto è conservato, alla prossima Crea riprende da dove si era fermata).

3 Fai la prima domanda

Scrivi la domanda nella casella in basso e premi Invia (o Enter). La risposta arriva con citazioni [[slug]], sezione Fonti verificate e riga di provenienza. Se la risposta non è nella wiki, l'app lo dichiara invece di inventare.

Comandi Knowledge Base

Tutti nel ☰ Menu → sezione Knowledge Base. La KB attiva (default demo) è mostrata nel badge in alto.

Comando Quando usarlo Cosa fa
Crea Dopo aver caricato documenti nuovi o modificati Compila solo le sorgenti nuove/modificate (mai quelle già completate); chunking, extract LLM, merge, citazioni verificate
Documenti Processati Vuoi vedere lo stato di avanzamento Mostra processati (ingested) e disponibili da processare (new/changed/error) in due gruppi
Gestione Documenti Vuoi vedere o eliminare le sorgenti caricate Elenco file con anteprima ed eliminazione
Archivia Vuoi conservare la KB con un nome Salva un bundle JSON negli archivi locali (rag_kb_<nome>)
Gestisci Vuoi passare da una KB all'altra Elenca, attiva, esporta o elimina le KB archiviate
Ripristina Hai un file di backup della KB Importa la KB da file JSON (sostituisce l'attiva)
Cancella Vuoi buttare la KB attiva e ricominciare Elimina il database della KB attiva e i marcatori
Riepilogo Dati Vuoi i conteggi complessivi KB, conversazione, archivi e configurazione raggruppati per tipo
Le compilazioni costano chiamate LLM (una per chunk): per il primo collaudo usa un modello economico e un documento piccolo.

Fare Domande e Leggere le Risposte

Inviare una domanda

Scrivi nella casella in basso e premi il pulsante Invia (verde) o Enter (Shift+Enter va a capo). Ogni domanda è indipendente: non c'è memoria tra domande, la query riparte sempre dalla KB. Con STOP interrompi una query in corso.

La query usa prima l'indice del catalogo e chiama l'LLM solo se serve (modalità llm ≤ 2 chiamate, llm-min 1, offline 0).

Leggere la risposta

  • Citazioni [[slug]] — ogni affermazione rimanda alla pagina wiki di origine.
  • Fonti verificate — solo citazioni verbatim (testo letterale trovato nella sorgente): una parafrasi corretta ma non letterale viene scartata.
  • Riga di provenienza — indica da quale documento/chunk deriva il contenuto.
  • Nessuna allucinazione — se la wiki non contiene la risposta, l'app lo dichiara esplicitamente.

Conversazione

Comandi nel ☰ Menu → sezione Conversazione. Lo storico resta visibile nell'output, ma le query restano indipendenti tra loro.

Comando Cosa fa
VisualizzaMostra lo storico della chat in formato testo
CancellaElimina lo storico e pulisce la vista (le query successive restano indipendenti)
ArchiviaSalva la chat corrente (solo storico) con un nome
GestisciElenca, attiva, esporta o elimina le chat archiviate
RipristinaImporta una chat da file JSON

Comandi LLM — panoramica rapida

Tutti nel ☰ Menu → sezione LLM. Ecco quando usare ciascuno:

Comando Quando usarlo Cosa fa Dove vedi il risultato
Test LLM Nuovo Vuoi confrontare i modelli già selezionati con lo stesso prompt Testa in sequenza tutti i modelli di un provider (stesso prompt) Spinner + Log + finestra riepilogo 84vw
Seleziona LLM Vuoi scegliere quali modelli compaiono nell'albero Apre elenco con checkbox per provider/modello Albero LLM aggiornato
Aggiorna LLM Vuoi scoprire nuovi modelli dai provider con chiave attiva Scarica + testa modelli, calcola voto Log + elenco per selezione
Reset LLM Selezione rotta o vuoi tornare ai default Svuota selezione e ripristina modelli da data/models/ Albero LLM ricostruito

Selezionare un Provider / Modello

Pulsante LLM in alto → albero provider/modelli. Clicca un provider per espandere i modelli, poi un modello per attivarlo. Il modello attivo resta visibile nel badge accanto (provider/modello, o LLM: ospite).

Puoi cambiare modello in qualsiasi momento (hot-swap) senza ricaricare la pagina. La finestra del modello influenza il chunking in build (chunk 8.000–40.000 caratteri).

Finestra Seleziona LLM

La finestra mostra solo i modelli con voto ≥6 e 4 pulsanti:

  • Salva — sostituisce completamente la selezione con i modelli spuntati
  • Aggiungi — unisce i modelli spuntati a quelli già presenti
  • Annulla — deseleziona tutti i modelli
  • Seleziona Attivi — seleziona solo gli LLM già attivi nell'albero, deseleziona gli altri — inverso di Annulla

Test LLM — guida passo-passo Nuovo

Obiettivo: confrontare, con un solo prompt, tutti i modelli che hai già selezionato per un provider. Utile per scegliere il più veloce o più adatto (anche per le compilazioni KB).

1. PromptScrivi il prompt nell'input
→
2. Avvia☰ → LLM → Test LLM
→
3. ProviderScegli il provider nella finestra
→
4. AttendiSpinner STOP + Log live
→
5. RiepilogoTabella Modello / Response / Tempo

Passo 1 — Prepara il prompt

Scrivi il prompt nella casella di input in basso. È obbligatorio: se manca, l'app mostra "digita prima un prompt di richiesta" e non parte.

Passo 2 — Apri Test LLM

☰ Menu → LLM → Test LLM (prima voce della sezione LLM).

Si apre la finestra Test LLM con il tuo prompt e la lista dei provider che hanno modelli selezionati, ciascuno con conteggio.

Se non hai modelli selezionati, l'app avvisa: "nessun modello selezionato — esegui Reset LLM o Seleziona LLM".

Passo 3 — Scegli il provider

Clicca il provider da testare. La finestra si chiude e parte il ciclo sequenziale (un modello alla volta, parametri uguali per tutte le prove).

Passo 4 — Durante il test

  • Spinner con STOP: clicca STOP e conferma per interrompere. La richiesta in corso viene annullata.
  • Log live: il pannello Log si apre da solo e registra ogni prova con provider/modello, dimensioni e tempo, oppure il codice errore.

Passo 5 — Finestra riepilogativa

Alla fine (anche dopo STOP) si apre la finestra Riepilogo [provider], larga 84vw, con tabella Modello / Response / Tempo o codice errore. Chiudi con X: provider/modello attivi vengono ripristinati.

Errori comuni: NO_KEY (manca API key), NO_MODEL (modello non in catalogo), 429 (rate limit), 5xx (provider sovraccarico).

Gestione delle API Key

Ottenere una API Key da un Provider

La API Key è una stringa segreta che identifica il tuo account presso il provider e abilita le chiamate ai suoi modelli. Si ottiene dalla console web del provider: crea un account, vai alla sezione API Keys e genera una nuova chiave. Copiala subito: molti provider la mostrano una sola volta.

  • Google Gemini — Vai su Google AI Studio, accedi con l'account Google e premi Get API Key → Create API key. Il piano gratuito copre l'uso normale.
  • Mistral AI — Vai su console.mistral.ai, apri API Keys e crea una chiave. Potrebbe servirti un metodo di pagamento o credito prepagato anche per i modelli minori.
  • Groq — Vai su console.groq.com, apri API Keys e premi Create API Key. Il piano gratuito ha limiti di richieste al minuto.
  • OpenRouter — Vai su openrouter.ai, apri Keys e crea una chiave. La maggior parte dei modelli richiede crediti prepagati; alcuni modelli free funzionano a costo zero.
  • Hugging Face — Vai su Settings → Access Tokens e crea un token di tipo Read. Serve per l'inferenza serverless sui modelli ospitati.
Se una chiave smette di funzionare, rigenerala dalla stessa console e sostituiscila nell'app: le chiavi possono scadere o essere revocate dal provider.

Aggiungere una Chiave API

Dal menu laterale, vai su API Key > Gestisci API Key e compila il modulo in alto:

  • Provider: scegli il provider della chiave dal menu a tendina
  • Nome: un'etichetta a piacere (es. personale) per distinguerla
  • API Key: incolla la chiave copiata dalla console del provider

Premi Aggiungi: la chiave compare nell'elenco sotto il suo provider, in forma mascherata. Puoi salvare più chiavi per lo stesso provider.

Attivare e Usare una Chiave

Ogni provider usa una sola chiave attiva alla volta: seleziona Attiva sulla riga da usare (viene evidenziata). Poi scegli provider e modello dal pulsante LLM, oppure usa LLM > Aggiorna LLM per scoprire i modelli con chiave attiva.

Senza chiave attiva il provider non risponde: vedrai NO_KEY o 401 (chiave non valida o scaduta).

Ripristinare le Chiavi Default

API Key > API Keys Default ricarica le chiavi di prova predefinite (offuscate in static/data/api_x.json, seminate al primo avvio).

Le chiavi di prova hanno limiti di utilizzo. Per un uso regolare, aggiungi le tue chiavi personali.

Sicurezza delle Chiavi

  • Le chiavi vengono memorizzate solo localmente nel tuo browser
  • Non vengono mai trasmesse a server esterni (tranne al provider LLM scelto)
  • Nell'elenco sono visibili in forma mascherata
  • Puoi eliminarle in qualsiasi momento dalla gestione API Key

Interfaccia Utente

Barra Superiore

  • Menu (icona hamburger) - Apre il menu laterale con tutte le opzioni
  • HELP - Apre il manuale rapido dei comandi
  • README - Apre la documentazione tecnica (readme.html) in una nuova scheda
  • Versione - Badge con la versione app (0.1.2)
  • Upload - Carica file .txt/.pdf/.docx/.odt come sorgenti
  • Badge KB - Mostra la KB attiva

  • Badge modello - Visualizza provider/modello attivi
  • Log - Console tecnica: avanzamento build, esiti query, tempi e token
  • Tema - Alterna tra tema scuro e chiaro

Aree di Lavoro

  • Area Output - Risposte con rendering Markdown, citazioni e Fonti verificate
  • Area Input - Scrivi qui domande e prompt per il Test LLM

Pulsanti di Controllo

  • Invia (verde) - Esegue la query sulla KB (come Enter)
  • Copia Output - Copia il testo dell'output negli appunti
  • Cancella Input - Svuota la casella di input
  • STOP (spinner) - Interrompe build o query in corso

Documenti e Sorgenti

Caricare Documenti

Pulsante Upload nella barra superiore. Formati supportati:

  • TXT - Testo semplice (anche .md)
  • PDF - Testo estratto pagina per pagina nel browser
  • Word (.docx) - Testo estratto nel browser
  • ODT - Documenti OpenDocument

I file diventano sorgenti della KB attiva: finché non lanci Crea, risultano come new in Documenti Processati.

Gestire le Sorgenti

  • Gestione Documenti - Elenco file con anteprima ed eliminazione.
  • Documenti Processati - ingested vs new/changed/error: sai sempre cosa resta da compilare.
  • Una sorgente modificata mantiene il suo ID e viene ricompilata alla prossima Crea; le pagine già estratte vengono aggiornate per aggiunta, mai cancellate.

Temi, Reset e Logout

Cambiare Tema

Pulsante Tema nella barra superiore: alterna scuro (default) e chiaro. La selezione viene salvata automaticamente.

Reset Completo

Menu > Reset cancella TUTTI i dati: database delle KB (wikijs:*), stato locale, conversazioni, chiavi API e configurazione provider.

Questa operazione non può essere annullata. Esporta prima con Archivia ciò che vuoi conservare.

Logout

Menu > Logout esce e torna al login. In locale il login è bypassato, quindi rientri subito come user_local.

Suggerimenti Utili

  • Domande indipendenti - Ogni Invia riparte dalla KB: per raffinare, riformula la domanda invece di conversare
  • Citazioni verbatim - Se una risposta manca, la causa è spesso una parafrasi: prova a chiedere con le parole del documento
  • Hot-swap LLM - Cambia provider/modello senza ricaricare; confrontali a parità di domanda con Test LLM
  • Compilazioni economiche - Usa un modello economico per la Crea e uno capace per le domande difficili
  • Markdown - Le risposte supportano formattazione Markdown (tabelle, codice, elenchi)
  • Retry e rate limit - Retry ×3 su errori transitori; sul 429 backoff adattivo e job in rate_limited invece di insistere
  • Interruzione - STOP interrompe build e query; le interruzioni 499 sono ignorate dalla UI
  • Telemetria minima - Solo eventi d'uso verso il worker WWWANALYZER (implementazione: static/js/services/sender.js, config in static/js/services/config.js); disattivata in automatico in ambiente locale
